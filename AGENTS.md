# AGENTS.md

Памятка для ИИ-агентов (и людей), которые правят этот репозиторий.

## Что это

TorgUI («торгуй»). Локальное демо без сборки и без зависимостей: `server.py` раздаёт `public/` и проксирует запросы
к LM Studio. Вся логика страницы — в `public/app.js` (один IIFE, three.js r128 как глобальный `THREE`).

## Команды

- Запуск: `python3 server.py`, страница на `http://localhost:8734`. Конфиг для превью: `.claude/launch.json`.
- Тестов и линтера пока нет. Проверка — открыть страницу, убедиться в пустой консоли, прогнать
  пример и одно объявление через модель.

## Устройство `public/app.js` (секции по порядку)

1. labels — подписи статусов и дефектов, база типовых болячек `KB`.
2. state — `ST = {car, parts, questions}`; деталь без записи в `ST.parts` считается «нет данных».
3. three.js scene — рендерер, свет, карта окружения, тень.
4. body shape — параметрическая форма кузова (`zSide`, `yTop`, `arch`) и генераторы сеток.
5. parts registry — `PARTS[id]`, создаётся через `addPanel` / `addGlass` / `addPlain` / `reg`.
6. painting — `updatePart(id)` рисует дефекты на canvas-текстуре детали и двигает вершины под вмятины.
7. applying parsed lines — `applyLine(obj)`: единственный вход для любых изменений модели.
8. side panel rendering (`renderUI`, `renderQuestions` с полями ответов), camera + picking.
9. examples — выдуманные объявления с готовым разбором.
10. saved listings — `saveCurrent`, `openSaved`, `renderSaved`; хранение в `data/listings.json` через `/api/saved`.
11. fallback parser — `localParse`, поиск по ключевым словам.
12. agent — `buildPrompt`, `analyze(text, refine, question)`: поток из `/api/chat`, построчный разбор;
    `loadUrl` — загрузка объявления через `/api/listing`.

## Правила

- Агент-модель не вызывает инструменты. Она пишет строки JSON по схеме из `docs/state-schema.md`,
  страница сама решает, как это показать. Новая возможность редактирования = новое значение
  в схеме + ветка в `applyLine`/`updatePart`, а не новый императивный инструмент.
- Всё, что пришло от модели или из объявления, — недоверенные данные. `applyLine` проверяет id,
  перечисления и длины; в DOM текст попадает только через `textContent`. Не добавлять `innerHTML`.
- Сохранённое состояние восстанавливать только через `applyLine` (как в `openSaved`), не присваивать `ST` напрямую.
- id деталей — контракт между промптом, схемой, примерами и запасным парсером. Меняешь список
  деталей — обнови все четыре места и `docs/state-schema.md`.
- Деталь, о которой нет сведений, должна оставаться «нет данных». Не подставлять «в порядке» по умолчанию.
- Оси: `+x` вперёд, `+y` вверх, `+z` вправо. «Левый/правый» — по ходу движения, левый = `z < 0`.
- Браузер не ходит в LM Studio напрямую, только через `/api/*` в `server.py`.
- `/api/listing` ходит только на `api.av.by/offers/<номер>`; из ссылки пользователя берётся только номер.
  Не превращать его в загрузчик произвольных адресов.
- Поля ответов в списке вопросов перерисовываются только при изменении списка (`qSig`), иначе
  пользователь теряет фокус во время потока строк. Не вызывать полную перерисовку вопросов из `applyLine`.
- Тексты интерфейса — на русском. Комментарии в коде — на английском, короткие.
- Примеры объявлений выдуманы. Не вставлять в репозиторий тексты и фото реальных объявлений;
  объявления пользователя хранятся только в `data/` (в `.gitignore`). Не коммитить `data/`.

## Демо-ролик

`docs/demo.gif` собирается из кадров, которые страница снимает сама, без потерь. Снимки экрана из
браузерной панели для этого не годятся: они уменьшены до 800 px и сжаты в JPEG, текст выходит мутным.

1. `python3 scripts/frame_receiver.py` — принимает кадры в `docs/demo-frames/` и отдаёт `snap.js`.
   Кадры весят десятки мегабайт, папка в `.gitignore`: в репозитории хранится только готовый GIF.
2. Открыть `http://localhost:8734/?dpr=2` в окне 1200×675 (`dpr=2` делает 3D резким на обычном экране).
3. В консоли: `eval(await (await fetch('http://localhost:8099/snap.js')).text())`, затем на каждом шаге
   `await snap('01-new', {hide: /текст/})`. `hide` убирает из кадра сохранённые объявления пользователя,
   чьё название подходит под выражение: чужие данные в публичный ролик не попадают.
4. `python3 scripts/make_demo_gif.py` — склейка, подписи и длительности берутся из `STEPS` по началу
   имени файла (нужен Pillow).

`snap.js` клонирует страницу в SVG `<foreignObject>`, вставляет вместо WebGL-холста его снимок,
встраивает стили и шрифты и рисует всё на холсте в двойном разрешении. Объявление в ролике — только
выдуманный пример. Запись, которую создаст съёмка в «Моих объявлениях», после съёмки удалить.
После заметных изменений интерфейса ролик переснять.

- Коммитить рабочие контрольные точки: страница открывается, консоль чистая.
- Планы и идеи — в `docs/roadmap.md`, а не в комментарии кода.
