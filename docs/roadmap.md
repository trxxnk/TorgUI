# Дальше

## Известные ограничения демо

- Кузов условный: коробчатый седан в пропорциях E34, без рестайлинга, туринга и версий.
- Место дефекта известно с точностью до зоны детали, а не до сантиметра.
- Фото не используются. Нужна модель со зрением и привязка снимка к ракурсу.
- Объявление вставляется вручную: у av.by нет открытого API.
- Стойки крыши и задняя панель не имеют своих id (относятся к крыше и крышке багажника).
- three.js и шрифты грузятся с CDN.
- Нет тестов. Первые кандидаты: `applyLine` (валидация) и `localParse`.

## Идеи развития

1. **Сравнение объявлений.** Состояние уже JSON, нужно хранить несколько `ST`, показывать две
   машины рядом и таблицу отличий по деталям.
2. **Внутренний режим.** Прозрачный кузов, агрегаты (мотор, подвеска, трансмиссия, выхлоп) как
   отдельные детали с той же схемой `part`.
3. **Фото.** Модель со зрением ставит `src: "photo"`; в карточке детали показывать снимок-источник.
4. **Загрузка по ссылке.** Браузерное расширение или серверный загрузчик страницы объявления.
5. **База болячек по версиям.** `KB` сейчас общий; разнести по моторам и годам.
6. **Настоящая 3D-модель.** GLB с именованными деталями вместо процедурной геометрии; id деталей
   остаются прежними.
7. **Оценка модели-агента.** Набор размеченных объявлений и сверка ответа модели с разметкой,
   чтобы сравнивать локальные модели и промпты.
