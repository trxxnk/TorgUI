# Архитектура

```
браузер (public/)                 server.py                    LM Studio
┌───────────────────────┐   GET /api/agent   ┌────────┐  GET /v1/models   ┌──────────┐
│ index.html, styles.css│ ─────────────────▶ │        │ ────────────────▶ │          │
│ app.js + three.js     │   POST /api/chat   │ прокси │  POST /v1/chat/   │ bonsai   │
│                       │ ─────────────────▶ │        │  completions      │          │
│  applyLine(строка) ◀──│◀── SSE-поток ───── │        │ ◀── SSE-поток ─── │          │
└───────────────────────┘                    └────────┘                   └──────────┘
```

## Поток разбора объявления

1. `analyze()` собирает промпт (`buildPrompt`): правила, список id деталей, текст объявления.
2. `POST /api/chat` с `messages`. Сервер сам подставляет модель, `stream: true`, `temperature: 0.1`.
3. Сервер пересылает SSE-поток LM Studio как есть.
4. Страница склеивает `delta.content`, режет по переводам строк и каждую законченную строку
   отдаёт в `tryLine` → `applyLine`. Строки, которые не начинаются с `{` или не парсятся, пропускаются
   (так отсеиваются рассуждения модели и markdown).
5. `applyLine` проверяет поля, пишет в `ST`, вызывает `updatePart(id)` и ставит детали вспышку.
   Поэтому модель меняется по ходу ответа, а не в конце.
6. Ни одной принятой строки или сеть упала — `localParse()` разбирает текст по ключевым словам.

## 3D-модель

Готового меша нет: кузов строится в коде из параметрических сеток.

- `zSide(x, y)` — полуширина кузова, `yTop(x)` — линия капот/пояс/багажник, `arch(x)` — вырезы арок.
- Каждая панель — отдельная сетка с UV 0..1 по всей детали и своей canvas-текстурой 256×256.
- Дефекты рисуются в текстуре: царапины, сколы, пятна ржавчины, тень вмятины. Перекрас — сдвиг
  оттенка и матовость. Вмятина дополнительно сдвигает вершины внутрь (направление посчитано заранее
  в `geometry.userData.inw`).
- Стёкла — полупрозрачная текстура, трещины рисуются линиями. Фары и фонари меняют цвет.
  Колёса наклоняются (`skew`) и приседают (`flat`). Отсутствующая деталь — красный каркас.
- Место дефекта на детали задаёт `zone`; в координаты его переводит `zoneUV` по раскладке детали
  (`side`, `top`, `wrap`, `glass`).

## Режимы показа

- «Как выглядит» — цвет кузова и нарисованные дефекты.
- «Карта данных» — заливка по статусу: в порядке, со слов продавца (ok с уверенностью ниже 0.5),
  дефект, серьёзно, нет данных. Цвета берутся из CSS-переменных, поэтому следуют теме.

## Почему так

- Декларативное состояние вместо инструментов: проще проверять, легко сравнивать две машины
  (два JSON), слабая локальная модель реже ошибается в одной строке, чем в цепочке вызовов.
- Прокси вместо прямого запроса: не нужен CORS в LM Studio, выбор модели в одном месте.
- Процедурная геометрия вместо скачанной модели: у каждой панели свои UV и id, нет вопросов
  с лицензией. Цена — условный внешний вид.
